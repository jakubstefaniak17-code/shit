# 0.2-A — Dynamic Research Runtime & Real Market Data Foundation

## Data contract

The research adapter downloads historical OHLCV bars through Yahoo Finance's Chart API and stores them as a canonical, immutable CSV plus manifest. Runtime replay reads only that local artifact: it never depends on a vendor request. The pinned sample contains AAPL, MSFT and SPY from 2025-01-02 through 2025-01-31 in `America/New_York`.

The interval is **one trading day**. This is an explicit foundation choice: a no-key daily archive is stable and reproducible, while inventing intraday bars would violate the real-data requirement. A later iteration may add a licensed intraday provider behind the same `MarketDataProvider` contract.

Prices use the `RAW` adjustment policy. Splits and dividends are not applied; this is a price-only research series, not a total-return series. The manifest records source, symbols, period, frequency, timezone, adjustment policy, corporate-actions contract, creation time and content hash.

## Quality and reproducibility

Loading rejects duplicate symbol/timestamp keys, cross-symbol gaps on observed trading timestamps, unsorted rows, naive timestamps, invalid OHLC relationships, negative volume or a content-hash mismatch. The committed artifact is the reproducibility boundary. Re-importing is intentional and explicit:

```bash
python tools/import_real_data.py
```

Provider downloads may be cached under `data/cache/`, which is ignored by Git. The canonical sample is committed under `data/market/`. Given the same canonical bytes, configuration, code commit and random seed, replay produces the same ordered events and result hash.

## Runtime boundary

The UI replays 60 ordered market events and projects features, decisions, orders, fills, ledger, positions and NAV only up to the selected cursor. Play, pause, step, speed controls, fill auto-pause and reset operate on that fixed event stream. Execution remains simulated and is labelled as such. This iteration contains no ML, Regime Engine, Meta Allocator, Portfolio Optimizer, live broker, live capital, L2/L3 model, Short Engine, Multi-Currency Engine or 0.2-B capability.

## Known limitations

- Yahoo's no-key endpoint is pragmatic rather than an institutional data entitlement; redistribution and production licensing must be reviewed before broader use.
- Daily bars do not model intraday path, spread, queue priority or market impact.
- The short sample is sufficient for runtime validation, not strategy-performance conclusions.
- The current demo deliberately emits only long AAPL intents; this does not constitute a general long/short engine.
